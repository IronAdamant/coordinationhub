# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

CoordinationHub is a shared coordination layer for multi-agent coding swarms: agent identity/lineage, document locking (incl. region locks), task registry, work-intent board, handoffs, and a live dashboard — all backed by SQLite. **Zero third-party dependencies in core** (pure stdlib; the `mcp` package is an optional extra for the stdio transport). Development is paused as of May 2026 (see the README retrospective); the codebase is stable and the release pipeline automated.

**`AGENTS.md` is the full agent-facing reference** (architecture detail, all MCP tools, dev commands, known issues). Large parts of it are machine-generated — read it before structural work.

## Commands

```bash
python -m pytest tests/ -q                      # full suite (~800 tests, ~60s, in-memory SQLite)
python -m pytest tests/test_locking.py -q       # one file
python -m pytest tests/ -k "release_lock" -q    # by keyword
python scripts/gen_docs.py                      # regenerate machine-owned doc sections
python scripts/gen_docs.py --check              # CI-style drift check (exit 1 on drift)
coordinationhub doctor                          # sanity-check an install
coordinationhub serve-sse                       # dashboard at http://127.0.0.1:9898
pip install -e ".[dev]"                         # dev install (Arch: system pip is PEP 668-managed)
scripts/release.sh                              # release automation (see RELEASING.md)
```

## Architecture (big picture)

Every MCP tool flows through the same deliberate layering (see "Layering Discipline" in AGENTS.md before deviating):

1. **Primitive** (`tasks.py`, `lock_ops.py`, …) — pure functions taking `connect: ConnectFn`, zero internal imports from each other.
2. **Subsystem** (`*_subsystem.py`, twelve of them) — owns `_connect`/`_publish_event`/authz, wraps the primitive.
3. **Engine facade** — `core.py`'s `CoordinationEngine` *composes* the twelve subsystems (no mixins/MRO) and exposes one-liner facade methods; its size is a deliberate LOC-policy exception.
4. **Dispatch** — `dispatch.py` `TOOL_DISPATCH` maps tool name → engine method (shared by both transports).
5. **Schema** — `schemas/<group>.py`, pure-data JSON schemas validated by the stdlib validator in `validation.py`.
6. **CLI** (optional) — parser tree in `cli_parser.py`, dispatch table in `cli.py`, handlers in `cli_<group>.py`.
7. **Hooks** (optional) — `hooks/base.py` `BaseHook` holds IDE-agnostic logic; `hooks/stdio_adapter.py` is the stdin/stdout event adapter installed by `coordinationhub init` (config in `~/.coordinationhub/hooks.json`).

Two transports share dispatch + schemas: `mcp_server.py` (stdlib HTTP/SSE server, also feeds the dashboard) and `mcp_stdio.py` (requires the `mcp` extra). Storage is isolated in `_storage.py` (pool, paths, schema init) with canonical table definitions only in `db_schemas.py` and migrations in `db_migrations.py`; `db.py` provides the thread-local connection pool (WAL, 30s busy timeout). Plugins (`plugins/`: dashboard, graph, assessment) register via `plugins/registry.py`.

## Invariants that bite

- **Machine-owned doc sections**: content between `<!-- GEN:... -->` markers in README.md, AGENTS.md, COMPLETE_PROJECT_DOCUMENTATION.md, LLM_Development.md, SECURITY_FIXES.md, wiki-local/spec-project.md is regenerated by `scripts/gen_docs.py` — never hand-edit inside markers; run the script after code changes (CI auto-commits drift).
- **Dispatch coverage**: `test_dispatch_coverage.py` enforces every tool in `TOOL_DISPATCH` has tests. Adding a tool without tests fails the suite.
- **Tiered LOC caps** (code-LOC as computed by gen_docs) — see "LOC Policy" in AGENTS.md; don't apply a flat 500-LOC rule to `core.py`/`cli_parser.py`.
- **Zero-dep CI**: `.github/workflows/*.yml` intentionally use no marketplace actions (raw `git`/tool-cache steps). Don't "fix" this by adding `actions/checkout`.
- **`findings/` and `plan/` are gitignored on purpose** (private audit notes). Publishable outcomes go through `SECURITY_FIXES.md`, redacted.
- **Wikifier is active here**: `monitored_paths.txt` + `exclude_patterns.txt` at root; per-file wiki entries live in `docs/wiki/<relpath>/<stem>.md` (mirrored tree). After editing a monitored source file: `wikifier record-change <file> "<reason>"`, update its wiki entry, `wikifier mark-green <file> "<evidence>"`. `file_health.md`, `pending_updates.md`, `library.md` are wikifier-managed — never hand-edit.
- **Dev log**: add an entry at the top of `LLM_Development.md` (reverse-chronological) for significant changes.

## Versioning

Single source of truth is `__version__` in `coordinationhub/__init__.py` (pyproject reads it dynamically). Tags `v*` trigger `release.yml` (build + GitHub Release + PyPI).
